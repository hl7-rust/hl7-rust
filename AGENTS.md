# AGENTS.md

Instructions for coding agents (Claude Code, Codex, or any other) working in
this repository. `CLAUDE.md` is a pointer to this file — keep this one
canonical and don't fork the content between the two.

## What this is

A small Rust crate + CLI that converts HL7 v2.5 messages from the typed
JSON representation the sibling
[`hl7-v2-from-er7-into-json`](https://github.com/hl7-rust/hl7-v2-from-er7-into-json)
crate produces back to pipe-delimited ER7 text — the inverse of that crate.
See `README.md` for the user-facing pitch and `spec/index.md` for the
exact, normative conversion rules — **`spec/index.md` is the single source
of truth for behavior.** If you change what the converter does, update that
file in the same change; if you're unsure whether a change is a bug fix or
a behavior change, check it against the spec first.

## Layout

```
er7 (dependency)     ER7 parsing, the value tree, escape sequences,
                      rendering. Not in this repo — see spec/index.md §7.
src/lib.rs            Public API: parse(), convert(), convert_with_options(),
                       Hl7Error.
src/json.rs             A minimal, dependency-free JSON reader (RFC 8259)
                       producing a Value tree (Object/Array/String/Number/
                       Bool/Null) — spec §2.
src/reconstruct.rs      Rebuilds the er7::Message value tree from a Value
                       tree: root unwrapping, group flattening, array
                       un-nesting, delimiter recovery, the positional
                       field/component/subcomponent rules, and
                       re-escaping — spec §3–§4.
src/main.rs            CLI: argument parsing, stdin/file I/O,
                       --terminator/--trailing-terminator/-o.
tests/integration.rs   Black-box tests through the public API, including
                       round trips through the sibling crate's own golden
                       fixtures (samples/*.json).
spec/index.md          Normative specification (source of truth).
samples/*.json          Example JSON input files, generated by running the
                       sibling hl7-v2-from-er7-into-json crate — see below.
```

Each module has unit tests in a trailing `#[cfg(test)] mod tests` block;
cross-cutting behavior (group flattening, array un-nesting, full-document
round trips, the CLI contract) is covered in `tests/integration.rs` instead.

## Working conventions

- **Rust edition 2024**, exactly one runtime dependency: the
  [`er7`](https://crates.io/crates/er7) crate. Keep it that way unless the
  user asks for another — this crate's whole value proposition is reversing
  the typed JSON mapping with nothing beyond the ER7 encoding layer itself,
  not even a JSON parsing dependency (`src/json.rs` is hand-written for
  exactly this purpose).
- **No HL7 v2.5 data-type dictionary, on purpose.** Reconstruction is
  positional: the number after a key's last `.` is always that level's
  1-based position, regardless of whether the name in front of it is a
  typed HL7 data type or a generic fallback name. Do not add a `types.rs`
  mirroring the forward crate's — if a bug looks like it needs one, it's
  more likely a bug in the positional logic; check `spec/index.md` §3
  first.
- **JSON arrays are the one thing this crate handles that its XML sibling
  doesn't.** Every place that needs "every occurrence of this key" goes
  through the `occurrences` helper in `src/reconstruct.rs` rather than
  assuming a bare value or hand-rolling array-vs-not logic inline — keep
  new code going through it too.
- Every public item must have a doc comment; `src/lib.rs` carries
  `#![warn(missing_docs)]` to enforce it. Private items with public-facing
  doc links (e.g. cross-references from a `pub mod`'s `//!` header) must
  not link a private item with `[`...`]` — use plain text/code-span
  references instead, or `cargo rustdoc -- -W missing-docs` will flag the
  broken intra-doc link.
- Match the existing doc style: a one-paragraph summary of *what* and,
  where the *why* isn't obvious from the code, a short rationale — see any
  existing `///` comment for the register to match.
- Before finishing a change, run:
  ```sh
  cargo test               # unit + integration tests
  cargo clippy --all-targets -- -D warnings
  cargo fmt --check
  cargo rustdoc --lib -- -W missing-docs   # confirms no undocumented public items
  ```
  All four are clean on `main`; keep them that way.
- New behavior needs a test. Prefer a unit test next to the code it tests
  for parsing/reconstruction rules, and an integration test in
  `tests/integration.rs` for anything that touches the public API surface,
  the CLI contract, or a full-document round trip.
- Fallback-first design: this crate never fails on unrecognized input below
  the header (unknown segments, unparseable positions, deeper nesting than
  the forward crate ever produces, an unexpected number/boolean scalar all
  degrade gracefully — see `spec/index.md` §5). Preserve that property.
- **Regenerating samples**: `samples/*.json` are the literal output of
  running the sibling `hl7-v2-from-er7-into-json` crate against its own
  `samples/*.hl7` (and, for `misc.json`, an ad hoc ER7 message exercising
  repetitions, the explicit null, escape sequences, and a Z-segment). If the
  forward crate's output shape changes, regenerate with
  `cargo run --manifest-path ../hl7-v2-from-er7-into-json/Cargo.toml -- <input.hl7>`
  and update the corresponding integration test's expectations.

## Making a spec-affecting change

1. Update `spec/index.md` first (or alongside the code) so it states the
   new intended behavior precisely.
2. Implement it, matching the module boundaries above.
3. Add/update tests that pin the new behavior.
4. Update `README.md` only if the change affects the user-facing summary or
   examples there.
5. Run the checks in the previous section.

## Non-goals (don't "fix" these without discussion)

- Adding HL7 table/vocabulary or JSON Schema validation — this crate is
  explicitly not a validator (`spec/index.md` §1).
- Adding an HL7 v2.5 data-type dictionary — see "No HL7 v2.5 data-type
  dictionary, on purpose" above.
- Recovering blank (non-null) repetitions the forward crate's own encoding
  already drops — this is a documented limitation of that crate's output,
  not a bug in this one (`spec/index.md` §5).
- A batch/multi-document input mode for JSON — the typed JSON mapping holds
  one message per document; there is no batch envelope convention to split
  on the JSON side (`spec/index.md` §5).
